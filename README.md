# 雨停以前

一个关于雨、记忆与未说完的话的治愈系消除游戏。

这是一个无需后端、无需构建工具的纯静态网页项目。打开 `index.html` 即可运行，也可以直接部署到 GitHub Pages。

## 游戏内容

- 8 × 8 棋盘，交换相邻元素，组成三个或更多相同元素后消除
- 五个章节：雨、叶、云、月、雾；每章拥有不同目标和步数限制
- 四连生成银星，五连生成金星；特殊棋可以触发行列或同色消除
- 三种道具：铁锤、换位、洗牌
- 情绪值、暖意、环境台词、雨声、风声和粒子效果会随游戏进程变化
- 章节地图与回忆日志，通关后解锁对应记忆
- 分数、章节解锁和回忆使用浏览器 `localStorage` 保存
- 音乐面板支持项目音乐、用户选择的本地音频、授权音乐文件夹和音频直链

## 如何游玩

1. 打开页面，点击“翻开章节”。
2. 在章节地图选择已解锁的章节。
3. 点击或拖拽两个相邻棋子交换位置。
4. 完成当前章节目标，或使用道具处理难以移动的局面。
5. 点击顶部“音乐”打开音乐面板，首次播放时点击“播放”授权声音。

浏览器通常会阻止没有用户操作触发的自动播放，这是正常的浏览器策略。音乐无法播放时，请检查浏览器是否静音、网络是否可用，以及音频地址是否为可直接播放的音频文件。

## 本地运行

项目没有依赖安装和构建步骤。最简单的方式是直接打开：

```text
index.html
```

也可以使用任意静态文件服务器预览，例如：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。

项目中的 `.tmp-server.js` 仅用于本地辅助预览，不是网页运行所必需的文件。

## GitHub Pages 部署

仓库已包含 `.github/workflows/static.yml`。向 `main` 分支推送后，GitHub Actions 会自动部署静态页面。

首次使用时，在仓库的 `Settings -> Pages` 中将发布来源设为 GitHub Actions。部署完成后，页面地址通常是：

```text
https://<用户名>.github.io/<仓库名>/
```

项目使用 Git LFS 管理 MP3 文件。工作流已配置为在部署前拉取 LFS 实体文件；如果更换部署方式，必须确保上传的是实际音频文件，而不是几十字节的 LFS 指针文本。

## 音乐资源

项目音乐位于 `music/` 目录，由 `music/manifest.json` 登记。每首曲目至少需要包含文件名和相对路径：

```json
{
  "version": 1,
  "tracks": [
    {
      "name": "我的音乐.mp3",
      "path": "我的音乐.mp3",
      "size": 123456
    }
  ]
}
```

`path` 相对于 `music/manifest.json`，不要写成 `/music/...`。项目会使用站点相对地址，因此部署在 GitHub Pages 的仓库子路径下也能正常加载资源。

如果仓库内的文件无法加载，可以为曲目增加 `url` 作为远程回退地址。远程地址必须指向可直接播放的音频内容，并且服务器需要允许跨域访问。请只发布自己拥有使用权的音频文件。

更多音乐目录约定见 [`music/README.md`](music/README.md)。

## 项目结构

```text
index.html                 页面结构和游戏界面
styles.css                 全部视觉样式与响应式布局
game.js                    游戏主控制器和系统编排
board.js                   棋盘规则、匹配、特殊棋和下落逻辑
data.js                    章节、目标、台词和存档常量
renderers.js               棋盘、角色和粒子渲染
audio.js                   Web Audio 程序化环境音效
music.js                   项目音乐与本地音频管理
ui.js                      界面切换、提示和文本系统
assets.js                  图片资源加载
assets/                    背景、图标和棋子素材
music/                     音频文件、清单和音乐说明
.github/workflows/         GitHub Pages 自动部署工作流
```

## 开发约定

- 仅使用 HTML、CSS 和原生 JavaScript，不引入 npm、CDN 或编译型框架。
- 棋盘规则放在 `board.js`，表现放在 `renderers.js`，页面交互放在 `ui.js`，系统编排放在 `game.js`。
- 程序化音效放在 `audio.js`；背景音乐和用户导入音频放在 `music.js`。
- 新增资源时使用相对路径，并同时考虑直接打开文件和 GitHub Pages 子路径部署。
- 修改玩法或持久化数据前，请先阅读 [`DEVELOPMENT_GUIDELINES.md`](DEVELOPMENT_GUIDELINES.md)。
